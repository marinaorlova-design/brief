# Сайт-бриф

Статический пошаговый бриф для клиентов. Чистые HTML/CSS/JS, без фреймворков
и сборщиков — можно сразу выкладывать на GitHub Pages.

## Файлы проекта

| Файл | Назначение |
|---|---|
| `index.html` | разметка трёх экранов: интро, форма, «спасибо» |
| `styles.css` | оформление, палитра, адаптив |
| `app.js` | вся логика: вопросы (массив в начале файла), навигация, автосохранение, отправка |
| `config.js` | два значения, которые можно менять без правки кода: адрес Worker'а и телеграм-юзернейм |
| `worker.js` | код Cloudflare Worker — деплоится отдельно, на сайт не кладётся |
| `privacy.html`, `offer.html` | заглушки под юридические документы — **нужно заполнить** |
| `assets/photo.jpeg` | фото для финального экрана |

## Как изменить вопросы

Все вопросы описаны массивом `SCREENS` в начале `app.js`. Каждый экран — это
`{ stage, fields: [...] }`, где `stage` — номер этапа (1–7), а `fields` —
вопросы на этом экране (обычно 2–3, максимум 5).

У каждого поля есть:
- `id` — уникальный идентификатор (используется как ключ ответа),
- `type` — `textarea` / `text` / `radio` / `checkboxGroup` / `links` / `files` / `consent`,
- `label` — текст вопроса,
- `hint` — необязательная подсказка под вопросом,
- `required` — обязателен ли вопрос,
- `important` — показать ли плашку «важно».

Чтобы добавить вопрос — добавьте объект в `fields` нужного экрана или создайте
новый экран в массиве `SCREENS`. Названия и описания самих семи этапов — в
массиве `STAGES` чуть выше.

## Локальный просмотр

Файлы не требуют сборки, но открывать `index.html` напрямую двойным кликом
не стоит — часть браузеров блокирует некоторые операции на `file://`.
Проще поднять любой локальный сервер, например:

```bash
python3 -m http.server 8080
```

и открыть `http://localhost:8080`.

## Публикация на GitHub Pages

1. Создайте репозиторий и закоммитьте в него всё содержимое этой папки
   **кроме** `worker.js` (он не нужен на сайте, но не страшно, если останется).
2. В настройках репозитория → Pages → Source укажите ветку `main` и папку `/root`.
3. Через пару минут сайт будет доступен по адресу вида
   `https://username.github.io/repo-name/`.

## Настройка приёма заявок в Telegram (Cloudflare Worker)

Пока `BRIEF_ENDPOINT_URL` в `config.js` пустой, форма работает полностью
локально: по нажатию «Отправить бриф» ответы никуда не улетают, но ничего
не пропадает — человеку сразу доступна кнопка «Скачать копию ответов».

Чтобы включить отправку в Telegram:

1. **Создайте бота** через [@BotFather](https://t.me/BotFather) → `/newbot`,
   сохраните токен.
2. **Узнайте chat_id**, куда бот будет присылать брифы:
   - добавьте бота в нужный чат/канал (или напишите ему в личку),
   - откройте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` после того,
     как отправите боту любое сообщение — в ответе будет `chat.id`.
3. **Разверните Worker** (нужен аккаунт Cloudflare, бесплатного тарифа достаточно):
   - через [dash.cloudflare.com](https://dash.cloudflare.com) → Workers & Pages →
     Create → вставьте содержимое `worker.js`;
   - или через CLI [Wrangler](https://developers.cloudflare.com/workers/wrangler/):
     ```bash
     npm install -g wrangler
     wrangler init site-brief-relay
     # вставьте код worker.js в src/index.js
     wrangler secret put TELEGRAM_BOT_TOKEN
     wrangler secret put TELEGRAM_CHAT_ID
     wrangler deploy
     ```
4. В настройках Worker'а (Settings → Variables) задайте секреты
   `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHAT_ID`. Необязательно —
   `ALLOWED_ORIGIN` (адрес вашего сайта на GitHub Pages), чтобы ограничить,
   кто может слать запросы на Worker; если не задать — разрешены все источники.
5. Скопируйте адрес задеплоенного Worker'а (вида
   `https://site-brief-relay.<ваш-субдомен>.workers.dev`) в `BRIEF_ENDPOINT_URL`
   внутри `config.js`.

После этого при отправке брифа в Telegram придёт:
- первое сообщение — сводка (имя, контакт, компания, срок, главное действие);
- затем по одному сообщению на этап с непустыми ответами (пустые вопросы не
  показываются, важные — помечены ⭐️, длинные этапы автоматически режутся
  на несколько сообщений из-за лимита Telegram в 4096 символов);
- следом — прикреплённые файлы отдельными документами.

Если Worker недоступен или упал — ошибка отправки просто логируется в
консоль браузера, а человек всё равно попадает на экран «Спасибо» с
возможностью скачать ответы файлом. Данные никогда не блокируют завершение
брифа.

## Что нужно донастроить вручную

- **`privacy.html` и `offer.html`** — сейчас это заглушки. Пришлите мне ссылку
  на действующий сайт или текст документов — перенесу политику конфиденциальности,
  оферту и реквизиты ИП один в один. Пока в подвале и в согласии стоят
  плейсхолдеры.
- **`assets/photo.jpeg`** — уже на месте, ничего делать не нужно.
- **Текст на финальном экране** («отвечаю в течение 1–2 рабочих дней») —
  сейчас это моё предположение, поправьте на реальный срок прямо в `index.html`
  (блок `.thanks-text--muted`).

## О дизайне

Один шрифт — **Manrope** (вариативный, вес 200–800), палитра: тёплый фон
`#F5EDE1`, текст `#241713`, бордовый акцент `#6E1423`, приглушённый синий
`#3C5A73`. Анимации сознательно оставлены лёгкими (CSS-переходы, без GSAP) —
это утилитарная форма, которой важнее не терять данные и грузиться быстро,
чем нести полный набор motion-приёмов будущего портфолио-сайта.

## Проверка перед сдачей

Пройдите бриф от начала до конца на мобильном и десктопном разрешении:
все этапы, валидацию обязательных полей, черновик (закрыть вкладку и
открыть заново), загрузку и удаление файлов, кнопки на финальном экране.
